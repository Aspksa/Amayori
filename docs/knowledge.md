# Знания 0.11

Раздел «Память → Знания» содержит карточки, фильтры и боковую панель. На телефоне карточка открывается внутри рабочей области и закрывается кнопкой возврата; прокручивается список или карточка, а не весь сайт. Существующая чёрно-золотая тема сохранена.

## Карточка и связи

Карточка хранит сущность, отношение и значение, тип (проект, человек, предпочтение, задача, решение или общее), темы, дату создания, дату изменения и источники. Источники содержат исходный текст пользователя и ID сообщения, если знание извлечено из архива. У старых записей текст источника может отсутствовать; интерфейс сообщает об этом явно.

Связанные карточки находятся по общей сущности или теме, с объяснением связи. Граф показывает сущности и подписанные отношения актуальных знаний. Темы и типы можно фильтровать; список загружается страницами по 30 карточек.

## Извлечение

Переключатель «Авторазбор» включает дополнительный запрос к выбранной модели Cloud.ru после нового сообщения пользователя. В этой версии он включён по умолчанию; его можно выключить в интерфейсе. `AMAYORI_AUTO_EXTRACT=0` принудительно отключает фоновый разбор. Текущий уже начатый запрос завершится, следующие не запускаются. Это расходует лимит Cloud.ru отдельно от ответа в чате. Извлечение не обучает веса модели.

Модель получает только текст пользователя и до 15 существующих карточек для согласования названий. Она должна вернуть до пяти явно сказанных полезных сведений с темой, типом и признаком единственного актуального значения. Ответ модели проверяется по структуре и длине полей. Результат ИИ может ошибаться: извлечённые знания помечены отдельно от введённых пользователем.

В окне «Извлечь» можно разобрать вставленный текст или поставить в очередь до десяти последних ещё не разобранных пользовательских сообщений. Старый архив не отправляется модели автоматически при установке обновления. Очередь выполняет один запрос за раз, хранится на диске и восстанавливается после перезапуска. Ошибочное сообщение повторяется только по явному запросу разбора. Максимум ожидающих сообщений — 30; если очередь переполнена, пропущенные сообщения остаются в архиве и могут быть разобраны позднее. Интерфейс показывает работу, ожидание и ошибки. Завершённые ID хранятся в окне до 2000 сообщений; карточки дополнительно устраняют повторные источники по ID.

## Повторы и противоречия

Точные повторы объединяются после нормализации регистра, пробелов, ё/е, типографских дефисов и завершающей пунктуации. Десятичные числа, адреса и внутренние знаки сохраняют различия. Все источники и темы остаются у одной карточки. Существующие точные повторы сворачиваются при запуске; прежние карточки сохраняются с отметкой объединения.

Похожие формулировки одного отношения предлагаются в боковой панели. Их смысл проверяет пользователь, затем выбирает «Объединить с этой карточкой». Прежняя карточка и исходная формулировка остаются в истории; повторное извлечение объединённой формулировки пополняет ту же карточку.

Для одного актуального значения (например, выбранной темы интерфейса) используется признак «Только одно актуальное значение». Извлечение может выставить этот признак; при ручном вводе он задаётся переключателем. Новое отличающееся значение становится кандидатом, прежнее остаётся актуальным. «Сделать актуальным» явно выбирает версию, переводя остальные значения этого отношения в историю. Возврат к прежней версии также сохраняет историю. Повторное упоминание исторического значения не активирует его автоматически. Многозначные отношения, например участники проекта, по умолчанию дополняются.

Контекст ответов и граф включают только актуальные карточки. Кандидаты, история и объединённые карточки не подмешиваются в ответы как действующие факты. Лексический архивный поиск по-прежнему может вернуть прежнюю переписку; системная инструкция предупреждает модель, что воспоминания могут быть ошибочными и устаревшими.

## Хранение и переход на PostgreSQL

Без базы карточки хранятся в `data/knowledge.json`, очередь — в `data/knowledge-extraction.json`. При выбранном PostgreSQL используется существующая таблица `amayori_facts` с дополнительной JSONB-колонкой `knowledge_meta`. Старые ID, источники и история сохраняются. Записи выполняются транзакционно; блокировка защищает от одновременного создания повторов. Недоступная настроенная база не подменяется локальным файлом.

Перед сменой хранилища остановите сервер и сохраните копию `data`. Перенос чатов выполняется существующей командой `npm.cmd run migrate:postgres`. После неё выполните `npm.cmd run migrate:knowledge`: локальные карточки со всеми версиями, темами, источниками и ID импортируются только в пустую таблицу знаний. Непустая таблица отменяет перенос. Исходный JSON остаётся на месте. Локальные ID сообщений в источниках и сохранённые тексты остаются историческими ссылками; числовые ID нового архива им не присваиваются. Пока локальные знания не перенесены, пустая база показывает понятную ошибку миграции, а не пустой список.

Текущая реализация читает набор структурированных карточек целиком для связей и версий; интерфейс показывает его порциями. При больших базах следующим этапом нужна индексация тем и серверная выборка связей. Новых рабочих зависимостей нет.

## Проверки

Основные API:

| Метод и маршрут                      | Назначение                                                                         |
| ------------------------------------ | ---------------------------------------------------------------------------------- |
| `GET /api/knowledge/facts`           | Список, счётчики и темы; фильтры `q`, `topic`, `kind`, `status`, `offset`, `limit` |
| `GET /api/knowledge/card?id=…`       | Карточка с источниками, версиями, расхождениями и связями                          |
| `POST /api/knowledge/facts`          | Ручной ввод `{subject,predicate,object,topic,kind,exclusive}`                      |
| `POST /api/knowledge/choose`         | Выбор актуальной версии `{id}`                                                     |
| `POST /api/knowledge/merge`          | Явное объединение `{targetId,duplicateId}`                                         |
| `POST /api/knowledge/extract`        | Извлечение из `{text}` или сохранённого пользовательского `{sourceMessageId}`      |
| `GET/POST /api/knowledge/extraction` | Состояние очереди / настройка `{enabled}`                                          |
| `POST /api/knowledge/extract-recent` | Постановка до десяти недавних сообщений, включая явный повтор ошибок               |
| `GET /api/knowledge/graph`           | Подписанные связи актуальных карточек                                              |

Модульные проверки покрывают повторы, одновременные записи, сохранение источников, версии, восстановление, многозначные связи, нормализацию чисел и адресов, очередь и разбор JSON модели. HTTP-проверка работает с временным хранилищем и подменённым Cloud.ru. Браузерная проверка использует настоящий локальный репозиторий карточек и проверяет формы, выбор версии, объединение, фильтры, экранирование текста и размеры 320–1920 px.

В Linux CI дополнительно запускается PostgreSQL 16 для проверки миграции старой схемы, параллельных записей, транзакций и истории. На компьютере можно задать `AMAYORI_TEST_DATABASE_URL` для такой же изолированной проверки: тест создаёт отдельную временную схему и удаляет её после завершения. Рабочая база приложения для теста не используется.
