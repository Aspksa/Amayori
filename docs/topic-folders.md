# Темы-папки и беседы — 0.13

Раздел «Память → Знания» показывает компактные папки. Нажатие открывает одно центральное окно с вкладками «Знания», «Беседы» и, при наличии вопросов, «Требует внимания». На телефоне окно занимает доступную область экрана. Источники, версии и чтение переписки открываются внутри него. Текущий чат, маршрут страницы и черновик остаются на месте.

## Темы и автоматический порядок

Папки — логические темы в существующей памяти. Физические каталоги на диске не создаются. Используется до двух уровней, например `Amayori / Дизайн`. Более глубокое имя сохраняет оставшиеся части через разделитель «·» на втором уровне. Уже существующие плоские темы остаются доступными; переносить их в искусственно придуманные проекты приложение не пытается.

При извлечении модель получает существующие темы и инструкцию использовать подходящее имя, создавая новое только при необходимости. Регистр, лишние пробелы и разные разделители пути нормализуются без дополнительного обращения к Cloud.ru. Название известной темы переиспользуется. Семантически похожие названия внутри одного проекта предлагаются для явного объединения. Автоматического слияния разных смыслов нет.

При объединении сохраняются карточки, ID, источники и история. События изменения темы записываются в метаданные. Последующее извлечение под прежним названием перенаправляется в объединённую тему. Знание может иметь несколько тематических связей, оставаясь одной карточкой. Счётчик родительской папки считает уникальные карточки и беседы.

В раскрытой карточке можно изменить тему. Ручное назначение фиксируется в истории; автоматическое извлечение повторного факта уважает выбранное пользователем распределение.

## Компактные знания и внимание

В списке показаны сущность, отношение и значение. Нажатие раскрывает единственный блок сведений непосредственно под строкой. Повторное нажатие сворачивает его. Источники и история версий доступны после раскрытия.

Отметка на папке появляется по фактическим вопросам: кандидат на замену значения, отсутствие подходящего источника, знание без темы, похожие названия тем, ошибка извлечения сообщения из связанной беседы. Общие ошибки неподключённой модели или очереди также видны в существующей строке состояния извлечения. Проблемы не приписываются произвольной теме.

Из проверки можно открыть карточку, выбрать актуальную версию, назначить тему, объединить похожие темы либо явно повторить разбор ошибочного сообщения. Повтор разбора обращается к Cloud.ru и расходует лимит. После успешного ручного повтора соответствующая ошибка очереди снимается.

## Одна беседа — одна строка

Общий архив теперь показывает беседы, а не каждую реплику отдельно. Для существующего диалога используется его сохранённое название. Для старых записей без диалога имя берётся из первого содержательного пользовательского сообщения, с удалением визуальных маркеров Markdown. Это короткий заголовок, а не сгенерированное моделью резюме. Для группировки и названий дополнительные запросы Cloud.ru не нужны.

Исторические записи без идентификатора беседы группируются по паузе более 30 минут; это временные сессии общения, а не гарантированное разделение по смыслу. Записи с явным `conversation`/`conversation_id`/`conversationId` используют его. Группировка — производное представление: исходная переписка не переписывается, не обрезается и не удаляется. Идентификатор сессии выводится из ID первого сообщения и сохраняется при добавлении реплик в ту же сессию.

Связь беседы с папкой определяется по сообщениям-источникам знаний, в том числе исторических версий. Для перенесённых источников с прежним локальным ID используется однозначное совпадение текста и даты. Неоднозначный текст не назначается случайной беседе. У темы с вручную введёнными знаниями может не быть связанных бесед — это отображается честно.

Полная переписка читается порциями по 50 сообщений с кнопками «Ранее» и «Далее». Поиск в общем архиве охватывает все сохранённые сообщения, возвращает строки бесед и при открытии переходит к совпавшему сообщению. Ссылка из знания также открывает нужную страницу и выделяет конкретное исходное сообщение. Представление архива кешируется до пяти секунд; после записи нового обмена и удаления сообщений кеш сбрасывается. Сообщение можно удалить внутри окна беседы с явным повторным нажатием; связанные знания забываются существующим механизмом. API управления диалогами `/api/conversations` сохранён отдельно от тематического представления `/api/conversations/grouped`.

## API

| Метод и маршрут                    | Назначение                                                           |
| ---------------------------------- | -------------------------------------------------------------------- |
| `GET /api/knowledge/folders`       | Папки, дочерние темы, уникальные счётчики и конкретные вопросы       |
| `POST /api/knowledge/topics/merge` | Объединение `{from,to}` с сохранением метаданных                     |
| `POST /api/knowledge/topic`        | Ручное назначение темы `{id,topic}`                                  |
| `GET /api/conversations/grouped`           | Список бесед; `q`, `topic`, `offset`, `limit`                        |
| `GET /api/conversations/item`      | Страница беседы; `id`, `offset`, `limit`, `messageId`; без `id` — поиск беседы по точному ID сообщения |
| `GET /api/conversations/source`    | Переход к источнику; `factId`, `messageId`                           |

Факты и тематические события сохраняются в прежнем локальном JSON или PostgreSQL. Новых рабочих зависимостей и отдельного сервиса нет. Выборка знаний по родительской теме включает её подтемы. Метаданные папок вычисляются сервером из канонических записей; клиент получает содержимое выбранной папки и страницы бесед по запросу.

Модульные проверки покрывают нормализацию и переиспользование тем, объединение с сохранением источников, ручное назначение, состав внимания, группировку и стабильность бесед, пагинацию старой переписки, неоднозначные источники и сброс кеша. HTTP-проверка работает с изолированным полным архивом и проверяет его неизменность. Браузерная проверка проверяет центральное окно, точный переход к старому источнику, отсутствие дублирования чата и размеры 320–1920 px. PostgreSQL-проверка дополнена тематическими событиями и повторным использованием прежних имён.
