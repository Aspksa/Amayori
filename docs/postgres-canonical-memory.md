# PostgreSQL — единая основная память Amayori

Если `AMAYORI_DATABASE_URL` задан, PostgreSQL хранит **основную историю переписки** в таблице `amayori_chat_log`. Чат, история и поиск воспоминаний читают её напрямую. Файл `data/chats.json` в этом режиме — **производный снимок для Project Golem**, а не независимое хранилище.

## Переход без потери данных

1. Сделайте резервную копию всей папки `data` и отдельно `data/chats.json`.
2. Установите PostgreSQL и pgvector без Docker, создайте БД и отдельного пользователя. Выполните `npm.cmd install`.
3. В окружении Windows установите `AMAYORI_DATABASE_URL` (не помещайте пароль в репозиторий).
4. **До обычного запуска** выполните `npm.cmd run migrate:postgres`. Команда импортирует локальную переписку только в пустую таблицу и проверяет количество сообщений. Если таблица уже содержит записи, импорт прервётся, чтобы избежать дубликатов.
5. Если есть `data/knowledge.json`, выполните `npm.cmd run migrate:knowledge` для переноса карточек в пустую таблицу знаний. Источники и версии сохранятся, исходный файл останется на месте.
6. Запустите `Amayori.bat`. Проверяйте `/api/memory/status` — режим `postgresql`.

Если база недоступна, чат в PostgreSQL-режиме возвращает ошибку, **не переключаясь незаметно на старую JSON-память**. Если PostgreSQL не настроен, остаётся прежний локальный режим. Снимок Golem обновляется после успешного сохранения переписки и при запуске; его ошибка не отменяет запись в базу. PostgreSQL и pgvector устанавливаются отдельно. Векторный поиск используется в контексте чата при заданной `AMAYORI_EMBEDDING_MODEL` с размерностью 384 и наличии проиндексированных записей. При сбое эмбеддингов сохраняется подбор эпизодов по словам; для Golem также остаётся Python-механизм построения эмбеддингов.

Не удаляйте исходную резервную копию до проверки истории, поиска и 3D-карты на своей Windows-машине.
